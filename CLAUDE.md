# Facilio Delivery Studio: notes for any Claude session

This project is worked on from two Claude accounts (personal and office), from the same folder (`D:\facilio\facilio-workshop-builder`) and from claude.ai/code. Nothing lives only in one account's chat: the repository on GitHub, `HANDOFF.md` and `docs/operations/DEPLOYS.md` carry the state between sessions.

## Starting a session
Run `/sync` first. It compares this folder with GitHub (`origin/main`), lists any uncommitted or unpushed work left by the other account, reads `HANDOFF.md`, and shows whether the live app is behind the code. Never discard another session's changes (no `git reset --hard`, no checkout of files) without asking.

## What to build next
Open `docs/ROADMAP-REQUIREMENTS.md`: Part A is the pending and not-checked list, Part B the master requirement in build order. Take one item at a time, tick it when done, and log the deploy number there.

## While working
- Finish a change, run `npm test`, commit, and push to `main` and `feat/simpler-studio` (`git push origin main`, then `git push origin main:feat/simpler-studio`). If the user said to wait until they have tested, commit locally and write "not pushed yet" in `HANDOFF.md`.
- Do not run two sessions on the same folder at the same time.
- **Put new files where they belong** (map in README.md): a plan goes in docs/plans, a design note in docs/design, a Claude/Outlook/Teams note in docs/integrations, an audit or report in docs/reports, a long how-it-works note in docs/reference, a deploy or job note in docs/operations; hand-run scripts go in tools/. A new page file in src/ gets one line in src/README.md under its stage; a new server file in work/server gets a first-line comment (work/README.md is built from it). Name plans and reports NAME-YYYY-MM-DD.md.
- **Keep the Claude integration in step.** Whenever a feature is added or changed, update the Claude side in the same piece of work: the connector tools (`work/work.json`, the tool object in `work/server/api.mjs`), the hand-off prompts (`src/claudelogic.js`, `src/claudehand.js`), the Open in Claude buttons on that page, the AI tasks, the skills text (`work/server/_skills.mjs`) and the Team Guide and Claude setup pages. A new page or record type needs a way for Claude to read it through the connector and a button that opens Claude with the short connector prompt. Run `node tests/claude_launch.mjs`, `tests/connector_skills.mjs` and `tests/ui/claude-handoff-check.mjs` afterwards. Never claim a real Claude app result without testing it there.
- Git has no identity on this machine. Commit with `git -c user.name="Dinesh R" -c user.email="dinesh.r@facilio.com" commit ...` and end commit messages with the Co-Authored-By trailer the session gives.

## Ending a session, or when tokens are running low
Run `/handoff`. It commits and pushes finished work, puts half-done work on a `wip/<name>` branch (never leave the only copy uncommitted), and rewrites `HANDOFF.md`. If tokens may run out suddenly, run it early; it is cheap.

## How the project works
- Plain JavaScript single-page app: `src/*.js` is bundled by `build.mjs` (esbuild) into `dist/`. Views register in `FWBViews`, actions in `ACT.<name>` (wired with `data-act` and `data-change`).
- Server function: `work/server/api.mjs` (plus `_ai.mjs` for AI, `_portfolio.mjs` for admin health). `work/work.json` lists the tools Otto (the Teams bot) can call.
- CSS: styles are layered in the order listed in `build.mjs`; later layers win. The build raises small text about 1px (`src/typescale.mjs`: 13px in the source shows as 14px, nothing under 11.5px; 15px and up unchanged; BRD and Excel previews and print untouched); `FWB_TYPE_SCALE=0` builds the source sizes. Overrides use `body ...:not(#_):not(#__)` with `!important`. `ui.css` is the last layer (the coss library, see `docs/design/UI-COSS-LIBRARY.md`).
- Preview locally: `node build.mjs`, then `node tests/ui/devserver.mjs 4173` and open http://localhost:4173/?nointro (`?intro=1` forces the opening animation). Local data is in `tests/ui/.devdata.json` (not committed).
- Tests: `npm test`. Also `npm run test:load` (100 projects, 100 people, AI limits) and `npm run test:scale`.
- CI: `.github/workflows/test.yml` runs `npm test` and the build on every push.
- Deploy: `/deploy`, or see `docs/operations/DEPLOY.md`. The site must stay under 50 MB extracted (about 41 MB now).

## Look and feel (the user's rules)
- **Master design system (user, 24 Nov 2026; replaces every older look rule, whose history is in git):** source `docs/design/master-design-system/` (MASTER_DESIGN.md, DESIGN_TOKENS.json, COMPONENT_PATTERNS.md, the Calendar and Stateflow add-on specs); plan and status `docs/plans/MASTER-DESIGN-SYSTEM-PLAN-2026-11-24.md`; the rules in short `docs/04-ui-ux-design.md`. Code: `src/masterds.css`, the last style layer. `build.mjs` turns its `:not(#DS)` into a 100-id chain so it wins over the older layers; new look rules go there, not in ui.css or projfx.css. One look for staff, customer and Admin; only menus, actions and data differ, by permission.
- **Calm colours (user, 24 Nov 2026: "do people like this funkiness and rainbow colours"; chosen with ui-ux-pro-max and ui-taste, "one accent, locked"):** one cool slate grey family carries the app. Facilio blue #1570EF is the only accent: the main action, "you are here" (soft blue #EFF5FF with deep blue #1849A9 text and a blue marker), progress and focus. Green, amber and red only for real status, always with words. Every menu and section icon is the same grey: no colour per module or per Team Guide section. Violet only on the Stateflow Test flow button. One gradient only: the projects home banner (logo violet-blue #201C5B into Facilio blue; user: "have the blue gradient here alone").
- **Each kind of control looks different:** page tabs are a text row with an underline; mini-tabs a segmented control; buttons have 10 px corners (primary solid blue, secondary white with a hairline, ghost, danger in red text); badges 6 px; cards 12 px with a hairline. The page header is compact and white: stage line, 32 px title, one line, the page's own actions top right. Contract intake is the model (Upload the MSA, then Analyse contracts, top right and not repeated below). Plus Jakarta Sans for titles and controls, Inter for reading text; nothing important under 12 px; sentence case. The build raises small text about 1px (`src/typescale.mjs`; `FWB_TYPE_SCALE=0` builds the source sizes).
- **Sidebar layout (user, 24 Nov 2026):** Expanded (icons + text) or Compact (the icon rail, the pages as stage tab cards), one choice per person and per view, in the account menu and in Tabs & Layouts, saved on the account (`PUT /api/me/nav`; `V.navPref` / `V.setNavPref` in src/shell.js). Defaults: compact for staff and customers, expanded for Admin. Unread updates show as a count on their rail stage and page tab (src/notifyclient.js).
- **Review pages are tables, not stacks of cards (user, 24 Nov 2026; audit `docs/reports/UI-UX-OVERHAUL-AUDIT-2026-11-24.md`, plan `docs/plans/UI-UX-OVERHAUL-PLAN-2026-11-24.md`):** anything to check, confirm, sign or tick is one `.rv-table` (group rows, a status as a dot and a word via `V.rvSt`, quiet text actions in the last column), with one quiet count line (`V.countStrip`) instead of figure cards, filters as selects in one `.rv-toolbar`, and one solid button per page. Calm states inside any table are a dot and a word; only attention states keep a tint. In the Expanded side menu the stage card row is left out (the menu lists those pages); there is no "You are here" box; Back is a quiet text link; the first pop-ups of a session merge into one. `node tests/ui/clutter-audit.mjs` measures buttons, solid buttons, badges, nested boxes and tab rows per screen.
- **Keep as designed:** the sign-in page on the logo violet-blue with the city art, the intro animation, Discover more, the Excel onboarding tool in its own light theme, the BRD and Excel previews, print. Light theme only; no dark mode.
- **No vendor UI names (user, 19 Nov 2026):** never name another company's design language or product UI in code, comments or docs.
- **Checks:** `node tests/ui/master-ds-check.mjs` (every menu entry and stage tab, both layouts, all three views, at 1920, 1366 and 1100 px: open state, page errors, overlap) and `tests/ui/button-colour-audit.mjs`. Everything the customer and the team see must look neat and uncrowded; keep answers short and in plain words, and say what was not checked.

## Things that go wrong here
- On Windows the Bash tool can mangle backslashes and newlines inside heredocs that contain quotes. Write scripts with the Write tool and run them with node.
- `node build.mjs` empties `dist/` first, so a build that fails leaves `dist/` empty; fix and rebuild.
- Never read `.credentials.json` or print secrets. Never sign in for the user, and never enter their credentials.
- facilio.work is deployed only through its connector. The app's review is pending, so only the owner and collaborators can open the live app.
